## 1. Что чиним и почему

Четыре пункта от пользователя:

| # | Что | Корень |
|---|---|---|
| 1 | В именах файлов «просто набор букв и цифр» вместо названия | `restrictfilenames: True` уничтожает кириллицу + префикс `{job_id}_` из 32 hex |
| 2 | При отмене плейлиста удаляются уже скачанные видео | `cleanup_job_files()` сносит всё по маске `{job_id}_*`, не разбирая, докачано или нет |
| 3 | Мало воздуха сверху в окне | `.content` и `.rail` имеют верхний отступ от макета, где над ними был нарисованный титлбар — а его мы не рисуем |
| 4 | Нет иконки приложения | `assets/app.ico` не существует; `.spec` его уже ждёт и молча собирается без иконки |

### Корень пункта 1 — проверено, не догадка

```
sanitize_filename('Как приготовить борщ: рецепт', restricted=True)  -> '_'
sanitize_filename('Как приготовить борщ: рецепт', restricted=False) -> 'Как приготовить борщ： рецепт'
sanitize_filename('5 минут / 100% успеха?',       restricted=True)  -> '5_100%'
```

То есть при `restrictfilenames: True` русское название схлопывается буквально в один символ подчёркивания. Отсюда файлы `._..mp4`, `__.mp4`, `._._._..mp4` в `downloads/`. Без этой опции yt-dlp сам заменяет запрещённые в Windows символы на безопасные полноширинные аналоги (`：`, `⧸`, `？`) и сохраняет кириллицу.

Скачивание с юникодным именем проверено на локальной заглушке: файл `Тестовое видео.mp4` создаётся и читается нормально.

### Решения пользователя

| Вопрос | Решение |
|---|---|
| Имя файла | **Чистое название**: `Как приготовить борщ.mp4`. Без префикса задачи, без id. Следствие: повторное скачивание того же видео yt-dlp пропустит («уже скачано») — это принято сознательно. |
| Плейлисты | **Полноценно**: скачанное не удаляется при отмене, каждое видео попадает в историю, в прогрессе «Видео 3 из 12», в конце «Скачано 12 видео». |
| Иконка | **Вариант D**: зелёная плашка `#3DDC84`, тёмная стрелка `#0F1B14` на скруглённом квадрате. Лучше всех читается в 16px и на тёмном фоне проводника. |

## 2. Ключевая идея правки: как теперь чистятся обрывки

Префикс `{job_id}_` в имени файла существовал ровно для одного — чтобы `cleanup_job_files()` нашла файлы своей задачи по маске. Убираем префикс — нужен другой способ. Он же чинит баг с плейлистом.

**Новый принцип: удаляем не «файлы задачи», а «незавершённые артефакты, появившиеся за время задачи».**

Два признака, оба обязательны:

1. **Файла не было до старта задачи** — перед загрузкой снимается снимок содержимого папки (`dir_snapshot`). Всё, что было раньше, — чужое, не трогаем никогда.
2. **Имя выглядит как обрывок** — `.part`, `.ytdl`, `.temp.<ext>`, `.f<цифры>.<ext>` (промежуточные видео/аудио дорожки до склейки ffmpeg).

Готовое видео не подходит под признак 2 и остаётся на диске — независимо от того, отменили загрузку или нет.

Почему это работает для плейлиста:

| Ситуация | Что на диске | Удаляется? |
|---|---|---|
| Видео докачано и склеено | `Название.mp4` | Нет — нет суффикса обрывка |
| Видео докачано без склейки | `Название.mp4` | Нет — то же самое |
| Видео оборвано на скачивании | `Название.mp4.part` | Да |
| Видео оборвано во время склейки | `Название.f299.mp4`, `Название.f140.m4a`, `Название.temp.mp4` | Да |
| Файл лежал в папке до задачи | что угодно | Нет — не прошёл признак 1 |

Побочная польза: перестанет копиться мусор вида `6_-_500.000.f140.m4a` и `6_-_500.000.temp.mp4` — сейчас такие файлы остаются после прерванных склеек и показываются в истории как обычные загрузки на гигабайты.

## Этап 1. Имена файлов и новая уборка обрывков

### Задача
Скачанный файл называется названием видео, а не набором символов. При отмене остаётся всё, что успело докачаться.

### Что менять — `app.py`

**1.1.** Рядом с `ANSI_RE` добавить константу:

```python
# По этим хвостам узнаём недокачанное: .part/.ytdl — обрывки загрузки,
# .temp.<ext> — файл склейки ffmpeg, .f<цифры>.<ext> — отдельные дорожки
# видео и звука до объединения. Готовое видео таких хвостов не имеет.
INCOMPLETE_RE = re.compile(r"\.(part|ytdl)$|\.temp\.[^.]+$|\.f\d+\.[^.]+$", re.IGNORECASE)


def is_incomplete_artifact(filename):
    """Обрывок незавершённой загрузки, а не готовое видео."""
    return bool(INCOMPLETE_RE.search(filename))
```

**1.2.** В `build_ydl_opts()` **удалить строку** `"restrictfilenames": True,`.

Больше ничего в этот словарь не добавлять: на Windows yt-dlp и без опций заменяет запрещённые символы сам (проверено).

**1.3.** В `download_worker()` заменить шаблон имени. Было:

```python
outtmpl = os.path.join(download_dir, f"{job_id}_%(title).150s.%(ext)s")
```

Стало:

```python
# Имя файла — название видео как есть. Префикса задачи больше нет:
# обрывки ищутся по снимку папки и хвостам имени (is_incomplete_artifact),
# а не по маске job_id, и пользователю больше не достаётся
# «f64202d6d3b0…__.mp4» вместо названия.
outtmpl = os.path.join(download_dir, "%(title).120s.%(ext)s")
```

120, а не 150: в имени теперь кириллица, а Windows считает лимит пути в 260 символов.

**1.4.** Там же, сразу после вычисления `download_dir` и до запуска yt-dlp, снять снимок папки:

```python
    # Что лежало в папке до начала задачи. Всё это — чужое: при уборке
    # обрывков такие файлы не трогаем, даже если имя похоже на обрывок.
    try:
        snapshot = set(os.listdir(download_dir))
    except OSError:
        snapshot = set()
    with jobs_lock:
        job = jobs.get(job_id)
        if job is not None:
            job["dir_snapshot"] = snapshot
            job["dir"] = download_dir
```

**1.5.** Переписать `cleanup_job_files()` целиком:

```python
def cleanup_job_files(job_id):
    """Убирает обрывки задачи: недокачанное и промежуточные дорожки.

    Готовые видео не трогает никогда — в том числе те, что успели
    докачаться из плейлиста до отмены. Файлы, лежавшие в папке до старта
    задачи, тоже неприкосновенны: снимок папки снимается перед загрузкой.
    """
    with jobs_lock:
        job = jobs.get(job_id)
        snapshot = job.get("dir_snapshot") if job else None
        directory = job.get("dir") if job else None

    # Записи о задаче нет — значит и снимка нет, и отличить свой обрывок
    # от чужого файла нельзя. В таком случае безопаснее не трогать ничего.
    if snapshot is None or not directory:
        return

    try:
        names = os.listdir(directory)
    except OSError:
        return

    for name in names:
        if name in snapshot or not is_incomplete_artifact(name):
            continue
        try:
            os.remove(os.path.join(directory, name))
        except OSError:
            pass
```

**1.6.** В `/api/download` в словарь новой задачи добавить два ключа:

```python
            "dir_snapshot": None,
            "dir": None,
```

`public_job()` их **не отдаёт** — наружу они не нужны.

### Допущения, которые надо проверить запуском

```
ДОПУЩЕНИЕ 1: без restrictfilenames yt-dlp не спотыкается о юникодные имена на
  всём пути — склейка ffmpeg, отдача файла по /api/file, «показать в папке».
  Проверить: скачать ролик с русским названием (из браузера и из start-desktop.bat),
             открыть его кнопкой «Папка» в истории.
  Если проводник не выделяет файл или ffmpeg падает: не подбирать транслитерацию
  наугад — остановиться и сообщить, какой именно шаг сломался.
```

### Проверка
В `tests/smoke_test.py`:

- `restrictfilenames` в настройках yt-dlp больше нет:
  `"restrictfilenames" not in svc.build_ydl_opts("out.%(ext)s", 720, lambda d: None)`
- в шаблоне имени нет префикса задачи: `"%(title)" in outtmpl` и `job_id` в нём не встречается — проверить через подменённый `svc.build_ydl_opts`, как уже сделано в блоке «качество доезжает до ydl_opts»;
- `is_incomplete_artifact` — таблицей:
  `'Видео.mp4.part'` → True, `'Видео.ytdl'` → True, `'Видео.temp.mp4'` → True,
  `'Видео.f299.mp4'` → True, `'Видео.f140.m4a'` → True,
  `'Видео.mp4'` → False, `'Обычное имя.mkv'` → False, `'f140.mp4'` → False;
- **главная проверка бага**: в папке рядом лежат `zzqa_ready.mp4` (как уже докачанное видео) и `zzqa_broken.mp4.part` (как обрывок), задача заведена вручную со снимком папки, не содержащим этих файлов; после `svc.cleanup_job_files(job_id)` — `zzqa_ready.mp4` **цел и байт в байт тот же**, `zzqa_broken.mp4.part` удалён;
- посторонний файл, попавший в снимок, не удаляется, даже если имя похоже на обрывок: `zzqa_alien.mp4.part` кладётся в снимок → после уборки он на месте;
- `cleanup_job_files("нет-такой-задачи")` ничего не удаляет и не падает;
- существующая проверка «обрывок не остался» (блок лимита размера) переписывается: вместо `glob(f"{job_id}_*")` — что в папке нет файлов, по которым `is_incomplete_artifact` истинно и которых не было до теста;
- скачивание с юникодным именем: заглушка `Stub` уже отдаёт файл по любому пути — запросить `f"{base}/Тестовое видео.mp4"` и убедиться, что `state["filename"]` содержит `Тестовое видео`, а файл существует на диске.

Прогон: `python tests/smoke_test.py` — 0 падений.

**Обязательно проверить, что новые проверки краснеют:** временно вернуть `"restrictfilenames": True` и старую маску `{job_id}_*` в уборке → проверки про имя и про уцелевший файл должны упасть → вернуть правку.

### Чего НЕ делать
- **Не переименовывать уже скачанные файлы.** В `downloads/` лежат видео пользователя с испорченными именами (`._..mp4` и подобные) — они остаются как есть. Массовое переименование чужих файлов не входит в задачу и необратимо.
- Не добавлять `windowsfilenames` — на Windows это уже поведение по умолчанию, лишняя опция только запутает.
- Не трогать `noplaylist: True`: ссылка вида `watch?v=X&list=Y` должна и дальше качать одно видео, а не весь плейлист.
- Не удалять файлы, которых нет в снимке-диффе, «на всякий случай».

## Этап 2. Плейлисты: прогресс, завершение, история

### Задача
Видно, какое видео из скольких качается. По окончании — «Скачано N видео». Каждое видео плейлиста попадает в историю со своим качеством.

### Что менять — `app.py`

**2.1.** В `hook()`, в ветке `d["status"] == "downloading"`, добавить в обновление задачи два поля из `info_dict`:

```python
            info_dict = d.get("info_dict") or {}
            ...
                    "playlist_index": info_dict.get("playlist_index"),
                    "playlist_count": info_dict.get("playlist_count") or info_dict.get("n_entries"),
```

`playlist_count` берётся с запасным вариантом: у разных экстракторов заполнено то одно поле, то другое.

**2.2.** В `/api/download` в словарь задачи добавить `"playlist_index": None, "playlist_count": None`, а в `public_job()` — отдать оба наружу.

**2.3.** В `download_worker()`, в успешной ветке, разделить два случая — одно видео и плейлист. Сейчас там безусловно берётся `info["requested_downloads"][0]`; для плейлиста этого ключа нет, из-за чего проверка `os.path.isfile(filename)` не проходит и задача завершается ошибкой «yt-dlp не сохранил файл» — **с последующей уборкой, которая до этапа 1 сносила все скачанные видео**.

Новая логика:

```python
        entries = info.get("entries") if info.get("_type") == "playlist" else None

        if entries is not None:
            # Плейлист: файлов много, каждый — отдельная запись в истории.
            saved = []
            for entry in entries:
                if not entry:
                    continue
                requested = (entry.get("requested_downloads") or [{}])[0]
                path = requested.get("filepath")
                if path and os.path.isfile(path):
                    saved.append((path, entry))

            if not saved:
                cleanup_job_files(job_id)
                finish_job(job_id, status="error",
                           error="Из плейлиста не скачалось ни одного видео.",
                           error_kind="generic")
                return

            for path, entry in saved:
                history_add({
                    "filename": os.path.basename(path),
                    "dir": os.path.dirname(path),
                    "title": entry.get("title") or os.path.basename(path),
                    "height": height,
                    "url": entry.get("webpage_url") or url,
                    "size": os.path.getsize(path),
                    "finished_at": time.time(),
                })

            first_path = saved[0][0]
            finish_job(
                job_id,
                status="finished",
                progress=100,
                filename=os.path.basename(first_path),
                title=f"{info.get('title') or 'Плейлист'} — скачано {len(saved)} видео",
            )
            return
```

Дальше — существующий код для одиночного видео, без изменений.

**2.4.** При отмене скачанные видео плейлиста уже остаются на диске (этап 1), но записей в журнале о них нет — в истории они покажутся без качества. Поэтому в ветке `except yt_dlp.utils.DownloadCancelled`, **после** `cleanup_job_files(job_id)`, занести уцелевшее в журнал:

```python
        # Уцелевшее после отмены — это докачанные видео плейлиста. Файлы
        # остаются, но записи о них нет: заносим, чтобы в истории было
        # видно качество, а не только имя файла.
        with jobs_lock:
            job = jobs.get(job_id)
            snapshot = (job.get("dir_snapshot") if job else None) or set()
            directory = (job.get("dir") if job else None) or current_download_dir()
        try:
            for name in os.listdir(directory):
                if name in snapshot or is_incomplete_artifact(name):
                    continue
                path = os.path.join(directory, name)
                if os.path.isfile(path):
                    history_add({
                        "filename": name,
                        "dir": directory,
                        "title": os.path.splitext(name)[0],
                        "height": height,
                        "url": url,
                        "size": os.path.getsize(path),
                        "finished_at": time.time(),
                    })
        except OSError:
            pass
```

Ставить это **до** вызова `finish_job(job_id, status="cancelled")`, но после `cleanup_job_files`, иначе в журнал попадут обрывки.

### Что менять — `templates/index.html`

**2.5.** В `pollProgress()`, там где заполняется `progressName`, показывать номер видео:

```js
    const part = (data.playlist_index && data.playlist_count)
      ? 'Видео ' + data.playlist_index + ' из ' + data.playlist_count + ' · '
      : '';
    progressName.textContent = part + (data.current_name || 'Загрузка…');
```

Больше в интерфейсе ничего не меняется: блок «Готово» покажет title, который сформировал сервер («Плейлист X — скачано 12 видео»), а кнопка «Показать в папке» откроет папку на первом файле.

### Допущения, которые надо проверить запуском

```
ДОПУЩЕНИЕ 2: для плейлиста extract_info возвращает info с _type == 'playlist'
  и списком entries, у каждого из которых есть requested_downloads[0]['filepath'].
  Проверить: скачать короткий плейлист из 2–3 роликов, посмотреть, что в истории
             появились все, а в блоке «Готово» — «скачано N видео».
  Если структура другая: не гадать по полям — вывести
  `print(info.keys(), (info.get('entries') or [{}])[0].keys())` в лог и вернуться
  с этим выводом к проектировщику.

ДОПУЩЕНИЕ 3: в info_dict внутри progress-хука есть playlist_index и
  playlist_count (или n_entries).
  Проверить: на том же плейлисте в прогрессе должно идти «Видео 1 из 3», «2 из 3»…
  Если полей нет: строка просто не появится (код это переживает) — сказать
  в отчёте, отдельно чинить не надо.
```

### Проверка
Настоящий плейлист в проверках не сымитировать — заглушка отдаёт один файл, а в интернет проверки не ходят. Поэтому:

- проверка на **регрессию бага** (главное): задача с непустым `dir_snapshot`; в папке появились `zzqa_pl_1.mp4`, `zzqa_pl_2.mp4` (докачанные) и `zzqa_pl_3.mp4.part` (оборванное); после `cleanup_job_files` — первые два целы, третий удалён;
- `public_job` отдаёт `playlist_index` и `playlist_count` (у обычной задачи — `None`);
- одиночное видео по-прежнему завершается как раньше: `run_job` на `/small.mp4` даёт `finished`, `filename` заполнен, в истории одна запись (проверка уже есть — убедиться, что осталась зелёной).

Плейлист целиком — **ручная проверка**, в отчёте написать явно: чем проверял, сколько роликов, что показала история.

### Чего НЕ делать
- Не вводить параллельные загрузки и очередь — одна задача за раз, как и было.
- Не пытаться отменять плейлист «по одному видео»: `/api/cancel` останавливает всю задачу, это не меняется.
- Не добавлять в интерфейс отдельный экран или список для плейлиста — только строка «Видео N из M» в прогрессе.

## Этап 3. Отступ сверху

**Визуальный этап. По завершении — показать пользователю.**

### Задача
Заголовку экрана и навигации не хватает воздуха сверху: в макете над ними был нарисованный титлбар, а в приложении его рисует Windows, и контент упирается в рамку окна.

**5.2. Раздел «Грабли»** — добавить пункт (формулировка обязательна, это дорого доставшийся факт):

> **`restrictfilenames: True` уничтожает кириллицу целиком.** Не «заменяет пробелы», как можно подумать по названию: `sanitize_filename('Как приготовить борщ: рецепт', restricted=True)` возвращает ровно `'_'`. И второй пункт:

> **Обрывки нельзя чистить по маске имени задачи.** Раньше файлы назывались `{job_id}_*`, и отмена сносила всё по этой маске — включая видео плейлиста, которые уже успели докачаться. **5.3. Раздел «Правила работы с проектом»** — уточнить формулировку про удаление: файлы пользователя удаляются только по кнопке «×» в истории; уборка обрывков не имеет права трогать ни готовое видео, ни файл, лежавший в папке до старта задачи.

## Ловушки

- **Порт 5000.** После проверок в браузере остаётся висеть python-процесс, следующий запуск отдаёт устаревшую страницу. Гасить сервер после каждой проверки.
- **`os.listdir` в уборке идёт по той же папке, куда качает yt-dlp.** Если файл занят (yt-dlp ещё не отпустил), `os.remove` кинет `PermissionError` — он гасится `except OSError`, повторная уборка через `threading.Timer(2.0, ...)` уже есть в коде и остаётся.
- **Снимок папки снимается один раз, до загрузки.** Если пользователь положит туда файл руками во время скачивания и файл будет похож на обрывок — уборка его удалит. Вероятность ничтожная, но знать про это стоит.
- **Проверки гоняются только из исходников** (`FROZEN = False`): юникодные имена, склейка ffmpeg и «показать в папке» в собранном приложении ведут себя иначе — отсюда обязательная ручная проверка через `start-desktop.bat`.
