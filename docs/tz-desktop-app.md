## Коротко

**Что получится.** Приложение для Windows: вставили ссылку — получили MP4, который открывается на телевизоре (с флешки или по сети), на телефоне (Android, iPhone) и на компьютере без установки кодеков. Ставится одним `VideoDownloader-Setup.exe` со страницы релизов GitHub, дальше обновляется само.

**Что меняется по сути:**
1. Браузерной версии и веб-сервера внутри больше нет. Окно разговаривает с Python напрямую.
2. Появляется гарантия совместимости: после скачивания файл проверяется и, если он «не для всех устройств», приводится к нужному виду.
3. Сборка, установщик и выпуск обновлений делаются на GitHub автоматически — по тегу версии.

**Что остаётся как есть:** дизайн и три экрана, история, правила сохранности файлов, тексты ошибок, плейлисты, пути настроек и загрузок.

**Рекомендуемый стек:** Python + pywebview (без Flask) + ffmpeg + Inno Setup + GitHub Actions. Почему не Tauri или Electron — раздел 2.1.

## 2. Решения

### 2.1 Стек

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Python + pywebview, без Flask** ← рекомендую | yt-dlp — Python-библиотека: прогресс, отмена и классы ошибок доступны напрямую. Переезжает вся проверенная логика (плейлисты, уборка обрывков, история, `humanize_error`) и готовый дизайн. Установщик и апдейтер уже наполовину написаны | Нужен WebView2 (в Windows 11 есть, в Windows 10 ставим из установщика). Exe от PyInstaller иногда ложно ловят антивирусы. yt-dlp обновляется только вместе с приложением — решается автоматическими релизами (2.6) |
| B. Tauri 2 (Rust) + `yt-dlp.exe` и `ffmpeg.exe` рядом | Маленький размер, готовый подписанный апдейтер | Всё переписать на Rust/TypeScript; прогресс — разбором текстового вывода `yt-dlp.exe`; Rust на машине не установлен |
| C. Electron + electron-updater | Самый зрелый автоапдейт из GitHub | Бэкенд переписать на Node, тот же разбор вывода `yt-dlp.exe`, установщик 150+ МБ |
| D. Python + PySide6 (Qt) | Нативные виджеты, WebView2 не нужен | Интерфейс рисовать заново, готовый дизайн в корзину, +100 МБ Qt |

Сильная сторона B и C — готовый механизм обновлений. Для A он собирается из Inno Setup, GitHub Actions и примерно 200 строк Python, и основа для него в проекте уже есть.

### 2.2 Страница ↔ Python: без веб-сервера

**Было:** Flask на случайном порту, страница делает 15 вызовов `fetch('/api/...')`.

**Стало:** `webview.create_window(..., js_api=Api())`, страница вызывает `await window.pywebview.api.start_download(url, quality)`. Портов нет, сервера нет, браузерного режима нет.

Что уходит вместе с Flask:
- `/api/file` и ветки `desktop_mode` — существовали только ради браузера;
- ручной ввод пути в настройках (остаётся «Обзор»);
- `start.bat`, порт 5000 и связанные с ним грабли;
- Jinja-шаблон: начальное состояние страница получает вызовом `api.bootstrap()` — версия, варианты качества, выбранное качество, папка, автообновление, найден ли ffmpeg, какой кодировщик;
- поверхность атаки: сейчас на порт `127.0.0.1` может постучаться любая программа на компьютере.

Что сохраняется: опрос прогресса раз в 500 мс (`api.get_progress(job_id)`) — логика страницы почти не меняется, меняется способ вызова. Всё долгое по-прежнему в своих потоках, методы `Api` возвращают управление сразу. Тяжёлый импорт yt-dlp — в фоне после показа окна, чтобы окно не ждало.

Страница — `ui/index.html`, `ui/styles.css`, `ui/app.js`, загружается по абсолютному пути (допущение 1). Соответствие роутов и методов — приложение А.

Для разработки: `python -m video_downloader --debug` — то же окно с инструментами разработчика WebView2.

### 2.3 «Играет везде» — профиль «Универсальный MP4»

Результат каждой загрузки обязан соответствовать профилю:

| Параметр | Значение | Почему |
|---|---|---|
| Контейнер | MP4, индекс `moov` в начале файла | ТВ и телефоны начинают показ и перемотку, не читая весь файл |
| Видеокодек | H.264 (AVC), профиль High | Единственный кодек, который аппаратно декодируют практически все ТВ, телефоны и ПК без расширений |
| Уровень | ≤ 4.1 до 30 кадров/с, ≤ 4.2 для 50–60 кадров/с | Ограничения аппаратных декодеров |
| Разрешение | короткая сторона ≤ 1080 (1920×1080; вертикальное 1080×1920) | 4K в H.264 требует уровня 5.1+, часть устройств его не тянет |
| Цвет | 8 бит, `yuv420p`, SDR BT.709 | 10-битный H.264 почти нигде не декодируется аппаратно; HDR на обычном экране выглядит блёклым |
| Частота кадров | ≤ 60 | — |
| Звук | AAC-LC, 2 канала, 48 кГц, 192 кбит/с | Opus, AC-3, E-AC-3 и 5.1 играют не везде |
| Дорожки | одна видео + одна звуковая, без встроенных субтитров | Лишние дорожки путают плееры ТВ |
| Имя файла | название видео, ≤ 120 символов | Как сейчас; замена `：` `｜` — только если подтвердится допущение 8 |

**Конвейер после скачивания:**

1. **Выбор формата** — как сейчас (`res:<качество>`, `vcodec:h264`, `acodec:aac`) плюс `ext:mp4:m4a`: чаще всего сразу приходит совместимый поток, и дальше делать ничего не нужно.
2. **Проверка** — `ffprobe` (вшивается рядом с ffmpeg) снимает параметры файла и сверяет с профилем.
3. **Решение** — самое дешёвое из подходящих:

| Что не так | Что делаем | Время |
|---|---|---|
| Всё совпало | ничего | 0 |
| Всё совпало, но `moov` в конце | перекладка без перекодирования с `+faststart` | секунды |
| Не подходит только звук | видео копируется, звук → AAC стерео | секунды — минуты |
| Не подходит видео (VP9, AV1, HEVC, 10 бит, HDR, 4K, > 60 кадров/с, уровень выше) | перекодирование в H.264 | минуты, зависит от длины и железа |

4. **Кодировщик** — автоматически: NVIDIA NVENC → Intel Quick Sync → AMD AMF → процессор (`libx264`). Доступность проверяется пробным кодированием одного кадра при первом запуске, результат запоминается. Сорвалось на видеокарте — тот же файл автоматически перекодируется процессором.
5. **Прогресс** — второй фазой в той же полосе: «Готовим для ТВ и телефона · 43 %» (`ffmpeg -progress`).
6. **Отмена во время подготовки** — процесс ffmpeg останавливается, временный файл удаляется. Скачанный исходник **остаётся**; в истории у него отметка «может не открыться на ТВ» и кнопка «Сделать совместимым».
7. **Успех** — результат ещё раз проверяется `ffprobe` и атомарно (`os.replace`) встаёт на место. Промежуточный исходник удаляется только после этого — это файл, созданный этой же задачей (правило снимка папки сохраняется).
8. **Ошибка подготовки** — исходник остаётся, жёлтый блок «Файл скачан, но может не открыться на телевизоре» с «Подробностями».
9. **История** — у готового файла отметка «ТВ · Телефон · ПК». Для файлов без отметки (скачанных до пересборки или после неудачной подготовки) — «Сделать совместимым»: создаётся **новый** файл рядом, исходник не трогается.

**Стартовые параметры кодирования** (уточняются на реальных роликах в плане этапа 2):
- процессор: `-c:v libx264 -preset medium -crf 20 -profile:v high -level:v 4.1 -pix_fmt yuv420p`
- NVENC: `-c:v h264_nvenc -preset p5 -rc vbr -cq 21 -b:v 0 -profile:v high -level:v 4.1 -pix_fmt yuv420p`
- звук: `-c:a aac -b:a 192k -ac 2 -ar 48000`
- всегда: `-map 0:v:0 -map 0:a:0 -sn -dn -movflags +faststart`
- HDR → SDR: цепочка `zscale` + `tonemap=hable`, на процессоре

**Файлы больше 4 ГБ.** Дело не в объёме флешки, а в её файловой системе. В FAT32 один файл не может быть больше 4 ГБ — даже на пустой флешке на 64 ГБ; Windows ответит «Файл слишком велик для конечной файловой системы». У exFAT и NTFS такого ограничения нет. Посмотреть, в чём размечена флешка: «Свойства» флешки → строка «Файловая система».

После скачивания файла больше 4 ГБ — спокойная подсказка, не ошибка: «Файл весит 6,2 ГБ. На флешку в FAT32 он не запишется — нужна флешка в exFAT или NTFS». Это строка в блоке «Готово», а не всплывающее окно. Рядом галочка **«Больше не показывать»**: выбор хранится в `settings.json` (ключ `show_fat32_hint`, по умолчанию `true`), вернуть подсказку можно в «Настройках». Не в `localStorage` — окно работает в приватном режиме, хранилище при каждом запуске пустое. Деление на части не делаем (решение 4).

### 2.4 Установка

- **Inno Setup 6**, установка в профиль пользователя (`%LOCALAPPDATA%\Programs\Video Downloader`): без прав администратора, обновления без запроса UAC. Основа — существующий `installer/video-downloader.iss`.
- **Постоянное имя файла** `VideoDownloader-Setup.exe`. Тогда ссылка `https://github.com/IIIJoKeRIII/video-downloader/releases/latest/download/VideoDownloader-Setup.exe` всегда ведёт на последнюю версию — её можно дать кому угодно и положить в README.
- **WebView2:** не найден — установщик запускает официальный загрузчик Microsoft (около 2 МБ, нужен интернет); не вышло — понятное сообщение со ссылкой.
- **Один экземпляр:** приложение держит именованный mutex, повторный запуск выводит на передний план уже открытое окно. Тот же mutex (`AppMutex`) не даёт установщику писать поверх запущенной программы.
- **Ярлыки:** меню «Пуск» всегда, рабочий стол — галочкой.
- **Свойства exe:** версия, название, издатель (ресурс версии в PyInstaller) — видно в «Свойствах» файла и в «Установке и удалении программ».
- **Удаление:** программа удаляется, **скачанные видео — никогда**. Настройки, история и логи — по вопросу «Удалить также настройки и историю?», по умолчанию «Нет». `[UninstallDelete]` для папки видео в `.iss` не появляется.


- В настройках: переключатель автообновления (есть), кнопка «Проверить сейчас», строка «Установлена версия 1.2.0», ссылка «Все версии» (страница релизов в браузере по умолчанию).
- `releases/latest` не видит черновики и пре-релизы — на них можно безопасно тренироваться.
- Откат: установщик прошлой версии берётся со страницы релизов вручную.
- Лимит GitHub без токена — 60 запросов в час с одного IP; проверка раз в 6 часов в него не упирается. Ответ 403 из-за лимита — тихое «не удалось проверить», не тревога.

**Репозиторий** сделан публичным 2026-09-12 (решение 1): проверка обновлений идёт без токена, релизы скачиваются без входа на GitHub. Токена в приложении нет и не будет — его достал бы любой.

### 2.6 Сборка и выпуск — GitHub Actions

**`ci.yml`** — на каждый push и pull request: Windows, Python 3.13, зависимости из `requirements.txt`, ffmpeg фиксированной версии, `python tests/smoke_test.py`.

**`release.yml`** — на тег `v*` (например, `v1.3.0`):
1. тег совпадает с версией в `version.py`, иначе стоп;
2. тесты;
3. скачать ffmpeg и ffprobe фиксированной версии, сверить SHA-256 (shared-сборка — два exe делят одни DLL, допущение 9);
4. PyInstaller: onedir, без UPX, с ресурсом версии;
5. **самопроверка собранного exe:** `VideoDownloader.exe --self-check` без окна проверяет импорт yt-dlp, запуск вшитых ffmpeg и ffprobe, наличие `ui/` и возвращает код 0;
6. Inno Setup → `VideoDownloader-Setup.exe`;
7. `SHA256SUMS.txt`;
8. релиз «Video Downloader 1.3.0»: текст — раздел версии из `CHANGELOG.md`, файлы — установщик и суммы.

**`yt-dlp-bump.yml`** — раз в сутки: есть ли новый yt-dlp на PyPI. Есть — поднять версию yt-dlp и patch-версию приложения, строка в `CHANGELOG.md`, тесты, коммит, тег и **сборка релиза в этом же запуске**. Сайты регулярно ломают yt-dlp, и без этого приложение «перестаёт качать» до ручного релиза. Режим — решение 3.

> **Ловушка:** тег, запушенный встроенным `GITHUB_TOKEN`, не запускает другие workflow. Поэтому сборка вызывается из `yt-dlp-bump.yml` напрямую (reusable workflow), а не ожидается от `release.yml`.

**Локально:**
- `tools/build.ps1` — та же сборка на своей машине, без публикации;
- `tools/release.ps1 1.3.0` — поднять версию, дописать `CHANGELOG.md`, коммит, тег, push. Запускается только по вашей команде.

**Версии:** SemVer. Пересобранное приложение выходит как **1.0.0** — 0.1.0 ни разу не выпускалась. Номер по-прежнему живёт в одном файле. Зависимости фиксируются точными версиями (`==`).

### 2.7 Подпись кода

Без подписи Windows при **первой** установке покажет SmartScreen «Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае». Обновления, скачанные самим приложением, метку «из интернета» не получают, и SmartScreen на них не срабатывает (допущение 6).

| Вариант | Цена | Замечания |
|---|---|---|
| **Без подписи на старте** ← рекомендую | 0 | Инструкция с картинкой в README, суммы SHA-256 в каждом релизе |
| SignPath Foundation | бесплатно для open source | Нужны публичный репозиторий и открытая лицензия; заявка рассматривается |
| Сертификат OV | сотни долларов в год | Выдаётся на аппаратный токен или облачный HSM; SmartScreen пропадает не сразу — репутация копится |
| Azure Trusted Signing | около 10 $ в месяц | Для частных лиц доступен не во всех странах — проверить |

## 4. Нефункциональные требования

- Windows 10 22H2 и Windows 11, x64. Установка, обновление и работа — без прав администратора.
- Приложение не открывает сетевых портов.
- Сетевые запросы — только к сайту видео (через yt-dlp) и к GitHub (обновления). Телеметрии нет.
- Новых Python-зависимостей нет; Flask уходит.
- Установщик — ориентир до 100 МБ (допущение 9).
- Окно появляется за 3 секунды на ПК с SSD.
- Все тексты по-русски.
- Скачанные файлы удаляются только кнопкой «×»; промежуточные файлы — только своей задачи. Удаление программы видео не трогает.
- Проверки не ходят в интернет и гоняются в CI на каждый push. Для совместимости — клипы, сгенерированные ffmpeg на лету.

**Этап 0 — что учесть:**

- **Локальная `main` отстаёт от GitHub на коммит «Delete».** Он убирает из репозитория `.claude/` (агенты `coder` и `planner`, `launch.json`, старый скилл `dev-flow`). Обычный `git pull` либо откажется (локально изменён `planner.md`), либо удалит эти файлы и с диска. Порядок: `git rm -r --cached .claude` — снять с учёта (файлы на диске остаются, папка уже в `.gitignore`); закоммитить текущее состояние; затем подтянуть коммит с GitHub.
